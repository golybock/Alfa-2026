# Как работать с репозиторием

## Ветки и PR

- В `main` напрямую не пушим. Только через PR.
- Одна задача — одна ветка от свежего `main`: `feature/news-collector`, `fix/feed-dates`.
- Коммиты маленькие и осмысленные: «Добавить парсер RSS Интерфакса», а не «fix», «upd», «asdf».
- Перед пушем: `git status` и `git diff --staged` — посмотри глазами, что уходит.
- Задача закрыта только после ревью Артёма, проверки работы и мержа. Открытый PR — ещё не готово.

## Что пушим

- Исходный код: `/backend`, `/web`, `/tools`
- Контракты (`/contracts`), миграции EF Core
- Конфиги без секретов: `appsettings.json`, `docker-compose.yml`, `.env.example`
- Lock-файлы: `package-lock.json`, `packages.lock.json`
- Документацию (`/docs`, README), `sources.json`, маленькие фикстуры и сиды

## Что НЕ пушим никогда

- **`bin/` и `obj/`.** Если в PR окажется хоть одна из этих папок, PR не принимается, а Артём будет крайне недоволен.
- `node_modules/`, `.next/`, `dist/`, `out/`
- `.env` и любые файлы с ключами, паролями, токенами
- `.vs/`, `.idea/`, `.vscode/` (кроме общих настроек, если договорились), `*.user`, `*.suo`
- Логи, дампы БД, временные файлы
- Сырые данные: CSV хакатона (`/data/raw`), собранные новости (`/data/news`)

Всё это уже есть в `.gitignore`. Не удаляй из него строки и не используй `git add -f`.

## Если всё-таки закоммитил лишнее

```bash
git rm -r --cached bin obj
git commit -m "Убрать bin и obj из репозитория"
```

Если в коммит попал ключ — сразу скажи Артёму. Ключ придётся считать скомпрометированным, просто удалить файл недостаточно.
