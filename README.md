# Бизнес-инсайты — персональная новостная аналитика для крупного бизнеса

Модуль для интернет-банка Альфа-Бизнес: превращает поток внешних новостей и аналитику Альфа-Банка в до 5 персональных инсайтов для конкретной компании — что произошло → почему это важно именно вам → последствия → действия, с позицией банка и источниками.

**Версия на дедлайн:** тег [`v1.1`](https://github.com/golybock/Alfa-2026/releases/tag/v1.1) (полный hash коммита — в описании релиза) · **Продуктовая документация:** [docs/00-overview.md](docs/00-overview.md)

---

## Быстрый старт

Нужны Docker с Compose 2.23+ и Git. Команды для PowerShell; в bash вместо `Copy-Item` — `cp`.

```powershell
git clone https://github.com/golybock/Alfa-2026.git
cd Alfa-2026
git checkout v1.1
Copy-Item .env.example .env
docker compose up -d --build
```

В `.env` впишите `LLM_BASE_URL` и `LLM_API_KEY` (ключ шлюза кейса); остальное можно не трогать. `POSTGRES_PASSWORD` в примере — пароль локальной базы, при желании замените. Не публикуйте `.env`.

Сайт: [localhost:8080](http://localhost:8080). Первый запуск занимает несколько минут: сборка образов, загрузка модели e5 (нужен интернет), импорт CSV. Пока Worker не загрузил компании, вход отвечает «Данные компаний ещё загружаются».

### Без ключа LLM или после исчерпания лимита

Если в `data/seed/` лежит снимок `demo.sql.gz`, PostgreSQL при первом создании базы (пустой volume) загружает его сам: готовые карточки CEO/CFO для демо-компаний, их шаги агента, расходы `llm_usage`, обзоры банка. Чтобы лента показывала этот снимок, а не живую недельную выборку, добавьте в `.env` строку `FEED_MODE=demo` и перезапустите API (`docker compose up -d`). **Без ключа этот режим обязателен:** в режиме `live` Worker при старте пересчитывает ленту на текущую неделю, а без модели новых событий нет — через неделю после даты снимка (25.10.2026) лента будет пустой. С ключом в режиме `live` Worker продолжит собирать и разбирать новости и сгенерирует карточки для новых событий (около 190 ₽ за неделю новостей).

В таком режиме интерфейс полностью кликабелен на готовых данных. Новые карточки, ответы чата и разбор новостей требуют ключа: без него задание завершается ошибкой «Требуется ключ модели», при исчерпании лимита — `budget_exhausted`, и интерфейс показывает этот статус. Снимок готовит команда: прогрев демо (`precompute-demo`, см. [A10](docs/a10-ranking.md)) и экспорт `python -I tools/export-demo-seed.py --database alfanews` — из копии базы удаляются сессии, кэш модели и полные тексты собранных статей (цитаты в карточках и событиях остаются), незавершённые задания помечаются неудачными.

Снимок загружается только в пустую базу. Чтобы начать заново, удалите volume: `docker compose down -v` (удалит все данные стенда).

## Вход на сайт

Учётки создаёт Worker при первом запуске, сразу после импорта CSV (обычно в первые минуты); до этого вход отвечает «Данные компаний ещё загружаются». Пароль у всех — `password`.

| Логин | Пароль | Кто | Доступ | Что показать |
| --- | --- | --- | --- | --- |
| `U_68157` | `password` | ЛПР | только эта компания (ОКВЭД 41, строительство), роли CEO и CFO | основной сценарий, переключение CEO/CFO |
| `U_71942` | `password` | ЛПР | только эта компания (ОКВЭД 16, обработка древесины), роли CEO и CFO | то же событие — другая позиция и причины |
| `U_258515` | `password` | ЛПР | только эта компания (ОКВЭД 46, оптовая торговля), роли CEO и CFO | третья отрасль |
| `demo` | `password` | ЛПР | все компании из `FEED_COMPANY_IDS`, у каждой роли CEO и CFO; после входа выбирает организацию и роль | сравнение компаний под одной учёткой |
| `admin` | `password` | оператор | без доступа к данным компаний; операторские endpoints (задания, PDF, проверка страниц) | повтор заданий, сверка PDF |
| `operator` | `password` | оператор | то же, что `admin` | |

Учётки по id компании создаются для каждой компании из `FEED_COMPANY_IDS` в `.env`. Каждый перезапуск Worker сбрасывает пароли этих учёток на `password`. Подробнее — [вход и учётки](docs/d04-auth.md).

Демо-компании выбраны в отраслях 41, 16 и 46: для них заполнена матрица `отрасль × фактор` (см. [ограничения](docs/04-limitations.md)). Отбор кандидатов — `data/reports/profile_candidates.json`.

## Сценарий проверки для жюри

1. Войти как `U_68157`, выбрать роль CEO → главная Альфа-Бизнеса с виджетом **«Персональные бизнес-инсайты»** *(критерий 09)*.
2. Открыть ленту: до 5 событий, у готовой карточки вместо заголовка новости — персональный вывод и строка «почему вы» *(01)*.
3. Открыть карточку: что произошло / почему это касается вас / последствия / действия / позиция Альфа-Банка / что мы о вас не знаем / проверки и ограничения *(02, 03)*.
4. Раскрыть «Почему я это вижу» — вклад каждого признака ranking и статус проверок *(01, 12)*.
5. Открыть доказательство и первоисточник; у каждого утверждения метка: «Факт из источника», «Данные компании», «Позиция Альфа-Банка», «Вывод ИИ», «Гипотеза» *(03, 04)*.
6. Задать вопрос в чате, например «Как это повлияет на наш кредит?»; затем вопрос не по теме — он отклоняется шаблонным ответом *(10)*.
7. Оценить карточку, нажать «Связаться с менеджером» (смоделированная эскалация, запись в журнал действий) *(06)*.
8. Переключить роль на CFO → тот же порядок ленты, другие последствия и действия.
9. Войти как `U_71942` → то же событие на другой позиции, с другими причинами и действиями.
10. **Новые, ранее не показанные новости** *(05)*: Worker собирает RSS по расписанию; на странице «Добавить материал» можно отправить ссылку на новость подключённого источника или загрузить PDF (до 10 страниц). Материал проходит разбор и ranking, попадание в ленту не гарантировано. Это работает в живом режиме (`FEED_MODE=live`) и с ключом модели.
11. Трассировка агента *(11, 12)*: `GET /api/insights/{id}/steps` (видно и в Swagger) — этапы плана, инструментов, черновика, проверок, критика и починки со статусом, кратким итогом и длительностью; реестр доказательств `E*` — в самой карточке. Полные данные шагов и вызовов модели (модель, токены, стоимость) — таблицы `agent_step` и `llm_usage`.
12. Стоимость: таблица `llm_usage` (PostgreSQL на `127.0.0.1:15432`), отчёт по стадиям — [docs/eval-report.md](docs/eval-report.md).

Те же шаги с ожидаемым результатом — [docs/test-scenarios.md](docs/test-scenarios.md).

## Архитектура

![Архитектура](docs/diagrams/product-logic.png)

Конвейер: сбор RSS → правила и точные дубли → фильтр заголовков (`yes/maybe/no`) → e5-фильтр явно посторонних тем → полный разбор в структурированное событие → профиль компании → score `событие × компания` → top-5 → агент (план → read-only инструменты → доказательства → карточка) → программные проверки → критик → не больше одной починки → карточка → чат по карточке. Подробно — [docs/02-system-logic.md](docs/02-system-logic.md).

| Компонент | Технология | Назначение |
|---|---|---|
| `web` | Next.js 16.4.2, React 19.3, TypeScript 5.9, Node.js 24.22.1 | имитация интернет-банка Альфа-Бизнес, лента, карточка, чат |
| `api` | .NET 10 (ASP.NET Core 10.0.13, minimal API) | вход, доступ, чтение ленты и карточек, постановка заданий, OpenAPI |
| `worker` | .NET 10 | очередь заданий: импорт CSV, профили, сбор и разбор новостей, OCR PDF, ranking, агент, чат |
| `migrate` | .NET 10, EF Core 10 | одноразовое применение миграций |
| `postgres` | PostgreSQL 17 + pgvector 0.8.7 | данные компаний, события, карточки, шаги агента, `llm_usage` |
| `tei` | Text Embeddings Inference cpu-1.9.4 + `intfloat/multilingual-e5-base` (int8), локально | фильтр тем, похожие события, поиск по аналитике |
| `gateway` | nginx 1.30.6 | `/api/` → API, остальное → web |
| LLM | DeepSeek-V4.1-Flash, GLM-5.3-Flash через шлюз кейса | см. таблицу ниже |

**Модели (только из разрешённого списка кейса):**

| Задача | Модель | Почему |
|---|---|---|
| фильтр заголовков, разбор новости, агент (план и черновик), починка, чат, проверка темы вопроса | DeepSeek-V4.1-Flash | в тесте новостей 4/5 полностью корректных разборов; точнее ссылается на доказательства — важно для трассируемости |
| критик, OCR аналитики | GLM-5.3-Flash | независимая проверка другой моделью; на PDF 3/3 страниц и 40/40 контрольных значений дешевле DeepSeek |

Модель каждой задачи меняется в `.env` (`LLM_*_MODEL`) без изменения кода. e5 — эмбеддинг-модель, не генеративная; запускается локально в контейнере, внешние AI-сервисы не используются. Агентный цикл, ranking и проверки написаны командой, без агентных фреймворков.

**Обмен данными между AI-компонентами** — JSON по схемам `contracts/schemas/` (генерируются из C#-типов `backend/AlfaNews.Contracts/`, передаются модели в `response_format`): факты с цитатами из источника, признаки клиента, вклады ranking, риски и возможности, реестр доказательств `E*`. Поле происхождения (`source_fact`, `bank_analytics`, `ai_inference`, `ai_hypothesis`) отделяет подтверждённое, позицию банка и вывод модели. Форматы HTTP — [contracts/README.md](contracts/README.md).

Технические схемы (БД, HTTP, Worker, OCR, LLM) — доска [«Альфа-Хакатон. Схемы»](https://www.figma.com/board/fdJyYxLUrAw5iMqAt9eMPH/?node-id=0-1); продуктовые — [доска продакта](https://www.figma.com/board/WbrIBm9CJqNkLrTFuaI7Gf) и `docs/diagrams/`.

## Безопасность AI-компонентов

- **Права доступа:** сессия в cookie; на каждом endpoint `AccessService` проверяет, что компания, роль, карточка, доказательство, страница PDF и задание доступны пользователю. Выбор компании и роли в интерфейсе — не авторизация.
- **Инструменты агента** — только чтение, компания берётся из задания, а не из ответа модели; данные других клиентов недоступны. Никакого SQL, shell и произвольных URL.
- **Журналирование:** каждый вызов LLM пишется в `llm_usage` (модель, токены, стоимость, ошибка), шаги агента и вызовы инструментов — в `agent_run`/`agent_step`, действия пользователя — в `user_activity` (без текста чата).
- **Prompt injection:** тексты новостей, PDF и вопросы передаются модели отдельными блоками как данные; проверка темы вопроса отклоняет попытки обойти правила шаблонным ответом без основного вызова.
- **Чувствительные данные:** модели не передаются сырые платежи, пароли, пути хранения; в чат не передаётся профиль компании — только карточка и её доказательства. Секреты только в `.env`, в репозитории их нет.
- **Сетевые запросы:** сбор новостей только с хостов из каталога источников, с таймаутом, лимитом размера и проверкой редиректов. Ручная ссылка принимается только с хоста включённого источника.
- **Опасные действия:** система ничего не выполняет за пользователя; «Связаться с менеджером» — эскалация к человеку. Операторские действия (повтор заданий, сверка страниц PDF) доступны только учёткам `admin`/`operator`. Изменяющие запросы принимаются только с адреса сайта (`PUBLIC_ORIGIN`).
- **Бюджет:** перед каждым вызовом резервируется оценка стоимости; при исчерпании дневного лимита стенда или общего ключа на шлюзе новые вызовы не выполняются, задание получает `budget_exhausted`, статус виден в интерфейсе.

## Переменные окружения

Скопируйте `.env.example` в `.env`. В примере только основные переменные; остальные необязательны, у них есть значения по умолчанию в `compose.yaml` и коде. Чтобы изменить, добавьте строку в `.env`.

### Основные (есть в `.env.example`)

| Переменная | Назначение |
| --- | --- |
| `HTTP_PORT` | Порт сайта (по умолчанию 8080). |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | База и пользователь PostgreSQL. Значения в `.env.example` фиксированные, менять их для проверки не нужно; пароль задаётся при первом создании volume. Это учётные данные базы, а не логин сайта. |
| `LLM_BASE_URL`, `LLM_API_KEY` | Адрес шлюза модели и ключ для живой модели. Без ключа работают только готовые данные. |
| `FEED_COMPANY_IDS` | Компании ленты; для каждой Worker создаёт учётку с логином = id компании. |
| `LLM_DAILY_LIMIT_RUB` | Дневной лимит расходов стенда на модель, ₽ (сутки с 03:00 МСК). Задания сверх лимита завершаются `budget_exhausted` и повторяются вручную. Ключ общий на команду: Worker дополнительно сверяется с расходом и лимитом ключа на шлюзе (`/key/info`). |

| `LLM_GLM_OUTPUT_ESTIMATE_RUB_PER_MILLION` | `50` | То же для выхода GLM. |
| `POSTGRES_HOST`, `POSTGRES_PORT` | `127.0.0.1`, `15432` | Только для запуска API и Worker без Docker (`dotnet run`): адрес PostgreSQL на хосте. |
| `Embeddings__BaseUrl` | `http://127.0.0.1:18081` | Только без Docker: адрес сервиса векторов на хосте. |

Модели задаются полными именами шлюза. Разрешены: `deepseek/deepseek-v4.1-flash`, `z-ai/glm-5.3-flash`, `google/gemma-4-26b-a4b-it`, `qwen/qwen3.6-35b-a3b`, `qwen/qwen3-vl-30b-a3b-instruct`, `moonshotai/kimi-k2.6`; другое Worker не запустит. Полоса `data` всегда последовательная; карточки CEO и CFO одного события не идут одновременно: вторая ждёт общий план. Настройка LLM, бюджет и проверка промптов — [A06](docs/a06-llm-gateway.md).

**Предметная настройка без изменения кода:** `data/taxonomy.json` — факторы, правила «продукт → фактор» и матрица `отрасль × фактор` (загружается при старте Worker); `data/sources.json` (шумные) и `data/sources-specialized.json` (специализированные) — RSS, разрешённые хосты, интервал опроса, надёжность; промпты — `backend/AlfaNews.Core/Prompts/` с версиями и хэшами в `versions.json`. Пороги ranking (`base ≥ 0,30`, `score ≥ 0,15`, окно 7 дней) — `RankingOptions`, пороги задаются в `.env`.

## Данные

- `data/df_Uid_data_hack.csv`, `data/df_Uid_payment_hack.csv` — данные кейса (компании и платежи), Worker импортирует их при первом старте; завершённый пакет при перезапуске пропускается. `df_Fid_Uid_link_hack.csv` (связи физлиц) не используется. Правила очистки и ручной запуск — [docs/a03-csv-import.md](docs/a03-csv-import.md), отчёт — `data/reports/import_report.json`.
- После импорта Worker строит `company_profile` и `group_profile` — [docs/a04-profiles.md](docs/a04-profiles.md).
- `data/*.pdf` — девять обзоров аналитики Альфа-Банка из кейса, метаданные — `data/bank_research/index.json`. Их распознанный и сверенный командой текст встроен в миграцию, поэтому повторный OCR при чистом запуске не нужен — [docs/a08-pdf-ocr.md](docs/a08-pdf-ocr.md).
- Новости собираются из RSS девяти включённых источников (каталоги выше) — [docs/d08-ingest.md](docs/d08-ingest.md). Полных текстов собранных новостей в репозитории нет: снимок `data/seed/` хранит заголовки, ссылки и цитаты.
- `data/seed/demo.sql.gz` — снимок базы с готовыми карточками для режима без ключа (см. «Быстрый старт»): демо-лента на 25.10.2026 20:16 МСК (новости 19–25.10, девять источников каталога): у U_68157 — 5 событий, у U_258515 — 4, у U_71942 — 2 (порог ленты прошло меньше событий — лента не добивается слабыми), по каждому событию готовые карточки CEO и CFO — 22 карточки с шагами агента и расходами; 101 разобранное событие недели.

Модель данных — [docs/data-model.md](docs/data-model.md), целевая структура хранения — `contracts/database.md`.

## Требования к окружению

Docker 24+ с Compose 2.23 или новее (в `compose.yaml` используются `configs` со встроенным содержимым); для Docker не меньше 4 ГБ памяти (рекомендуется 8); около 8 ГБ диска под образы, сборку и volumes; интернет для первой загрузки e5, сбора новостей и LLM (в режиме снимка после первого запуска не нужен). Версии зафиксированы: `packages.lock.json` в каждом .NET-проекте (сборка с `--locked-mode`), `web/package-lock.json` (`npm ci`), `global.json` (.NET SDK 10.0), `web/.nvmrc` (Node.js 24.22.1); образы Docker — с точными тегами (`compose.yaml`, Dockerfile).

## Ограничения

Матрица `отрасль × фактор` заполнена для ОКВЭД 41, 16, 46; приоритизации типов вызовов внутри бюджета нет; связи через физлиц не используются; ручная разметка качества (релевантность top-5, TTV) не проведена; живая лента обновляется опросом, без SSE; карточка иногда падает на проверке чисел после починки — есть кнопка «Повторить». Подробно: [docs/04-limitations.md](docs/04-limitations.md).

## Обслуживание

Пересборка без удаления данных PostgreSQL, PDF и загруженной модели:

```powershell
docker compose -p alfa-news -f compose.yaml down
docker compose -p alfa-news -f compose.yaml build --no-cache
docker compose -p alfa-news -f compose.yaml up -d
```

Существующий PostgreSQL volume сохраняет прежний пароль: изменение `.env` не меняет пароль уже созданного пользователя. Для обычного обновления volume не удаляйте. PostgreSQL доступен локально на `127.0.0.1:15432` (внутри Compose — `postgres:5432`).

`web/package-lock.json` хранится в Git, установка — `npm ci`. Пять high-предупреждений npm audit относятся к одной цепочке ESLint (eslint-config-next → fast-glob → micromatch → braces), исправления для braces 3.0.3 пока нет; `npm audit fix --force` не применять.
