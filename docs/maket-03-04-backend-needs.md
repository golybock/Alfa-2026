## Страница «Добавить материал»: закрыто PR #23, подключено на фронте

Страница `/materials` и кнопка в шапке ленты работают на живом API под обычным пользователем `demo`.

| Что было нужно | Как закрыто | Как используется на фронте |
| --- | --- | --- |
| Загрузка PDF и список документов для обычных пользователей | `POST` и `GET /admin/documents` доступны любому авторизованному, флаг `can_add_materials` в `MeResponse` | Страница и загрузка включаются по `can_add_materials`; индикатор: передача файла в процентах, затем «Распознаём страницы: N из M» |
| Ручная новость по ссылке | `POST /admin/news` (нужны все пять полей `ManualNewsRequest`, заполняется только `url`) | Блок «Или ссылка на новость»: сервер возвращает job, страница опрашивает его; ошибка сервера («Ссылка не с сайта подключённого источника…») показывается как есть |
| «Ваши загрузки» | `uploaded_at` и `uploaded_by_me` в `DocumentSummaryDto` | Список только своих PDF, новые сверху |
| Статус «Ждёт ключа модели» | `llm_key_required` | Бейдж «Ждёт ключа модели» и пояснение |

## Что осталось на стороне backend

| Что нужно | Что есть сейчас |
| --- | --- |
| Список ранее отправленных ссылок: сейчас job по ссылке видно только в текущей сессии страницы | После перезагрузки страницы отправленные ссылки в «Ваши загрузки» не видны, остаются только PDF. Нужен список ссылок пользователя (например, `GET /admin/news`) |
| Тело запроса `POST /admin/news` без обязательных `source_id`, `title`, `text`, `published_at` | Сервер отвечает «Некорректный запрос», если какого-то из пяти полей нет в JSON. Фронт отправляет все пять с `null` |

Лимиты на странице указаны по бэкенду: 50 МБ и 50 страниц (в макете было 30 страниц).

## Что сделано только на фронте

- Метка для типа `neutral` называется «Неопределённость» вместо «Нейтрально». В контракте тип остался `neutral`.
- Тема новости в верхней строке превью ленты убрана: в новом макете её нет.
- Блок «Почему показано» убран из карточки, как в макете. Причины отбора остались в панели «Почему я это вижу».
- Подзаголовок шапки карточки собирается из первого утверждения блока «Что произошло» и ссылки на новость из его доказательств.

## Что стоит согласовать

- В блоке «На чём основан вывод» всегда показаны обе строки дисклеймера, как в макете. Раньше вторая («Вывод ИИ не является позицией Альфа-Банка») показывалась только при `bank_view.status = not_found`.
- Номер места (`rank`) в шапке карточки в новом макете отсутствует, он остался только в панели «Почему я это вижу».

## Сделано на backend по странице «Добавить материал» (25.10)

Контракт обновлён (`npm run contracts:sync` уже выполнен), описание — `contracts/http.md`.

1. Загрузка PDF и список документов (`POST/GET /admin/documents`, `GET /admin/documents/{id}`) открыты всем вошедшим (с 25.10 и учёткам компаний, `U_68157` и т. п. — решение для демонстрации). В `/me` поле `can_add_materials` — по нему показывать страницу и кнопку. Проверка страниц и повтор заданий — только оператор.
2. Решение по доступу: страница доступна любой учётке с компаниями (`demo` и учётки компаний), оболочка банка открывается. Оператора в оболочку без компании не пускаем.
3. D17 сделан: `POST /admin/news` с `{ "url": "..." }` (`source_id` необязателен) → 202 `AcceptedResponse`, статус — `GET /jobs/{id}`. Принимается только ссылка с сайта подключённого источника, иначе 400 со списком сайтов в `message` (РБК, Минфин, правительство, ЦБ, Коммерсантъ и другие из `sources-specialized.json`). Задание: done со stage `collected` или `duplicate`; failed с `news_unavailable`, `news_empty`, `news_outside_window` (старше семи дней). Новость идёт в обычный разбор с высшей важностью и попадёт в ленту после разбора и обновления ленты, если пройдёт отбор для компании. Текст без ссылки не принимается.
4. В `DocumentSummaryDto` добавлены `uploaded_at` и `uploaded_by_me` — для фильтра «Ваши загрузки».
5. «Ждёт ключа модели» — отдельный флаг `llm_key_required` в `DocumentSummaryDto` и `DocumentResponse`, а не новое значение `ocr_status`: `UploadStatusBadge` перебирает все значения `OcrStatus`, и новое значение сломало бы сборку фронта. При флаге `ocr_status` = `failed`; у страниц `error` объясняет, что после настройки ключа нужен повтор.

## Сделано на backend по оставшимся пунктам (25.10, после PR #23–24)

- `POST /admin/news` принимает `{ "url": "..." }` без остальных полей: в `ManualNewsRequest` все поля необязательные. Отправка всех пяти с `null` тоже работает.
- `GET /admin/news` — ссылки, отправленные текущим пользователем, новые сверху, до 50: `job_id`, `url`, `title` (заголовок собранной статьи или null), `status`, `stage`, `error` (как в `GET /jobs/{id}`), `created_at`. Пример — `contracts/examples/manual-news-list.json`.
- `/admin/documents` и `/admin/news` доступны любому вошедшему, включая учётки отдельных компаний (`can_add_materials` у всех true) — так задумано для демонстрации.

## Правки по ревью и «Почему вы» (25.10)

- Список источников на странице материалов приходит с сервера: `GET /admin/news/sources` — включённые источники, специализированные первыми; выключенный ФНС больше не показывается.
- Метка нейтрального последствия — «Нейтрально», как в уточнении к D06 (не «Неопределённость»).
- `/materials` экспортирует `instant = false`, как остальные страницы группы `(bank)`.
- «Почему вы» в ленте — фраза модели `insight_why_you`; пока карточка не готова, вместо неё короткие метки причин через «·». В карточке фраза `why_you` стоит первой строкой блока «Почему это касается вас».
