# A10: score и недельная лента компании

Ранжирование выполняет код, без LLM. Каждое слагаемое становится причиной «почему показано» с доказательствами `E*`.

## Словари

`data/taxonomy.json` — единый каталог факторов, правил «продукт → фактор» и матрицы чувствительности отраслей. Worker синхронизирует его с таблицами `factor`, `product_factor_rule`, `sector_sensitivity` при каждом старте (`TaxonomyCatalogLoader`), как каталоги источников. Строки, которых нет в файле, удаляются. Файл проверяется: неизвестный фактор, вес вне [0,1] или знак не из `positive/negative/mixed` отменяют загрузку целиком.

Матрица сейчас заполнена для трёх демо-отраслей (41, 16, 62) и помечена `reviewed_by: draft`: это черновик весов, его нужно проверить до демо. Для остальных отраслей строк нет, признак `factor` для них равен 0 и отмечен `known=false` — это не доказанное отсутствие связи.

Те же факторы и полный справочник ОКВЭД2 передаются в извлечение новостей, поэтому теги событий совпадают с кодами ранжирования.

## Формула

`FeedRanking` считает шесть признаков в [0,1]:

| Признак | Значение |
| --- | --- |
| okved | 1, если среди ОКВЭД2-тегов события есть отрасль компании |
| factor | максимальный вес матрицы для отрасли компании и факторов события |
| product | 1, если правило связывает фактор события с продуктом компании |
| country | 1, если страна события есть среди стран ФТС компании |
| cp | максимальная из входящей и исходящей долей внешних платежей с компаниями затронутых отраслей; направления не складываются |
| group | максимум матрицы или правила продукта у другой компании той же GROUP_ID; ID этой компании не раскрывается |

`base = .25 okved + .25 factor + .20 product + .10 country + .15 cp + .05 group`, `recency = 2^(-ageDays/7)`, `score = recency × source.reliability × base`. Роль и наличие позиции банка в формулу не входят. Допуск: хотя бы один признак больше нуля, `base ≥ 0.20`, `score ≥ 0.15`, публикация попадает в окно с 00:00 МСК шестого предыдущего дня до `as_of`. Сортировка — score, дата публикации, ID; не больше пяти событий; слабые события ленту не добивают.

Веса, пороги, `CpEnabled` и `PrecomputeInsights` задаются секцией `Ranking` (`RankingOptions`), сумма весов должна быть равна 1. В контракте признаки — `RankingFeatureCode`, поле `has_bank_view` из `RankingResult` удалено.

## RefreshFeed

`FeedRefreshService` загружает профиль, профили группы, словари и события окна, считает score и перезаписывает `feed_snapshot` компании: `FeedItemDto` с причинами, вкладами и реестром доказательств. Затем для каждого отобранного события и ролей CEO/CFO ставит `GenerateInsightJob`, если карточки этой версии ещё нет (в том числе упавшей: её повторяют вручную). Карточки появляются по событию, а не по таймеру: после разбора новости `EnqueueForEventAsync` считает формулу для компаний из `Feed:CompanyIds` и ставит RefreshFeed только тем, для кого событие прошло порог. Порог задаётся в `.env`: `RANKING_MIN_BASE` и `RANKING_MIN_SCORE` (Compose передаёт их в `Ranking__MinBase` и `Ranking__MinScore`). Суточный таймер `Feed:RefreshIntervalSeconds` только освежает снимок; существующие карточки повторно не генерируются.
