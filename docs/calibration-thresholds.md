## Склейка пересказов (`Embeddings:DuplicateMinSimilarity`, сейчас 0,93)

- Из 49 пар ≥ 0,93 настоящих пересказов одного факта примерно 13. Остальные — разные обновления одного сюжета (Brent 108 → 109 → 113 → 115 долларов, курс ниже 83 и ниже 82 рублей, разные тезисы одной пресс-конференции ЦБ), противоречащие сообщения («MOL опровергла продажу доли» и «MOL договорилась о выкупе», 0,971) и даже несвязанные («ЦБ сохраняет курс доллара 82 рубля» и «финансовые результаты банка „Санкт-Петербург“», 0,943).
- Пересказы встречаются и ниже порога: «Мишустин о „Силе Сибири“» 0,927, IT-ипотека 0,921, недельная инфляция 0,05% 0,904. По косинусу пересказ от обновления не отделяется.
- Защита «в новости нет чисел, которых нет в событии» отсекает почти всё: даже в оценке сверху (числа события — весь текст старой новости, а не только извлечённые факты) она пропускает 7 из 49 пар ≥ 0,93, и из них пересказы только 2 («Шереметьево», «Сила Сибири»). Среди пропущенных — «MOL опровергла» ↔ «MOL договорилась», то есть потеря противоположного факта. В реальном коде числа события берутся из заголовка и извлечённых фактов, поэтому склеек ещё меньше.
- Цена ошибок несимметрична: ложная склейка навсегда теряет новость (событие не создаётся), пропущенная — стоит одно извлечение (~0,5–1,2 ₽) и, возможно, повторную карточку.

Решение (Артём, 23.10): склейка по e5 выключена — `DuplicateMinSimilarity` по умолчанию 1, остаются точные дубли по SHA-256 и URL. Если включать снова — не ниже 0,97 и с ручной проверкой на большей выборке.

## Похожие новости для агента (`Embeddings:SimilarNewsMinSimilarity`, сейчас 0,84)

- 0,84–0,86 (1 435 пар): в основном «та же тема экономики», но разные события — ставка ЦБ Турции рядом со ставкой Банка России, офисная аренда рядом с мониторингом МСП, разные новости банков.
- 0,86–0,88 (605 пар): чаще один сюжет — решение по ставке и реакция на него, топливный рынок, курс рубля.
- ≥ 0,88: один сюжет и его продолжения.

Решение (Артём, 23.10): порог по умолчанию 0,86. Инструмент возвращает до пяти ближайших, поэтому порог важен, когда по сюжету мало новостей: при 0,84 агенту доставались нерелевантные «похожие».

Выборка: в `alfanews_a07_calib` импортированы CSV и профили, 75 новостей (25 общего потока и 50 специализированных) прошли фильтр заголовков и извлечение DeepSeek с рассуждениями: 63 события, 8 отклонено фильтром, 4 сбоя извлечения, 51,65 ₽. Компании — три из `FEED_COMPANY_IDS`: U_68157 (41, строительство; кредит, лизинг, гарантия, зарплатный проект), U_71942 (16, обработка древесины; депозит, лизинг) и U_258515 (46, оптовая торговля; кредит, лизинг, зарплатный проект). Матрица — CSV продакта (веса только по силе канала).

Каждая пара «событие × компания» (189 пар) размечена по шкале 0–3 из [inputs.md](../contracts/inputs.md) по смыслу заголовка, без просмотра score. Разметка предварительная, её нужно просмотреть: `data/cache/calib/relevance.csv` (вне Git), там же скрипты повтора формулы (сверены с C#-снимком: 0,558 против 0,564, разница — только момент расчёта). Полезных событий (метка ≥ 2) в недельном окне: 9 у строительной компании, 1 у деревообработки, 4 у оптовой торговли.

Что изменено (`ranking-v2`, `taxonomy-v2`):

- Веса признаков: factor 0,25 → 0,30, product 0,20 → 0,15; `MinBase` 0,20 → 0,30, `MinScore` 0,15 без изменений. Смысл порога: фактор с весом 1 проходит сам (0,30), фактор 0,5 — вместе с продуктом (0,15 + 0,15), продукт без фактора отрасли (0,15) — нет. Раньше продукт плюс группа давали 0,25 и проводили почти любую экономическую новость.
- Матрица: «41 × стоимость кредита» 0,5 → 0,75 (лимиты льготной ипотеки и проектное финансирование — главный канал для застройщика; без этого событие с меткой 3 не попадало в топ-5), «46 × ключевая ставка» 0,5 → 0,75 (решение по ставке для оптовика с кредитом и лизингом не слабее условий кредитования). Остальные веса, каналы и знаки — как у продакта.
- Правило «зарплатный проект → налоги» удалено: налоговый тег получает почти любая новость (рассрочка «РусНефти», газ в Северном море), и правило пропускало её всем клиентам с зарплатным проектом.

Что весами не исправить. У оптовой торговли шесть событий с тегом `key_rate` получают одинаковый base 0,425 — решение ЦБ (метка 3) рядом с «Набиуллина: инвестиции 43 трлн» (0) и «РСПП о жёсткой ДКП» (1), и их порядок решают минуты публикации. Модель ставит факторный тег на любое упоминание. Улучшить можно только в извлечении — см. следующий раздел. Кроме того, okved почти всегда 0 (модель редко ставит отрасль компании), cp мал (доли платежей 5–26%), group = 1 у всех трёх компаний (в группах есть клиенты с кредитом) — это постоянный сдвиг, порядок не меняет. Выборка мала (63 события за неделю, у деревообработки одно полезное событие), веса стоит пересмотреть на следующей неделе потока.

## Воспроизведение

Скрипты разбора пар лежат вне репозитория (scratchpad сессии); база `alfanews_a07_calib` сохранена. Запросы: пары `1 - (a.embedding <=> b.embedding)` по `news_raw` в окне ±3 дня; защита чисел — регулярное выражение `\d+(?:[,.]\d+)?`, как в `NewsLines.Numbers`.

Регрессии, которые стоит исправить следующей итерацией промпта:

- Правило «корпоративное событие — без макрофактора» сняло отраслевые теги с важных для застройщика новостей: проектное финансирование Газпромбанка потеряло «стоимость кредита», лимиты льготной ипотеки — «стоимость кредита» (осталось «регулирование»), развязка ЦКАД — «спрос на строительство» (осталась «логистика»). Нужна оговорка: сделка или финансирование, показательные для отрасли, получают отраслевой фактор.
- Тег `key_rate` по-прежнему у шести событий, в том числе у реплик Набиуллиной без решения.
- Решение ЦБ по ставке попало в ленту двумя событиями (две статьи; во второй модель на этот раз сочла центральным решение, а не реакцию Мурычева). Склейка по e5 выключена калибровкой, поэтому одинаковые сюжеты в ленте нужно разводить при отборе: например, не ставить в одну ленту два события с косинусом e5 ≥ 0,93 (в выборке такие пары — один сюжет). Это изменение отбора `FeedRanking.Select`, пока не сделано.

Промпт 2.2.0 оставлен: в сумме он лучше, а регрессии точечные.
