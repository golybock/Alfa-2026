# Сбор новостей из RSS и HTML-статей (D08)

Worker собирает новости из источников `data/sources.json` и сохраняет сырой текст в `news_raw`. LLM, score и e5 здесь не участвуют: `ParseNews` обрабатывает A07.

## Как это работает

1. При старте Worker читает `data/sources.json` (путь можно задать `Sources__CatalogPath`, иначе берётся `Data__InputPath`) и обновляет таблицу `source`. Источник включается, только если в файле `enabled=true` и `validation_status=checked`.
2. Планировщик каждые 30 секунд проверяет, какие включённые источники пора опросить (`last_checked_at + poll_seconds` уже наступило и источник не занят активным заданием), и ставит для них задания `CollectNews`: отдельное задание на каждую группу с одинаковым `poll_seconds`.
3. Обработчик для каждого источника загружает ленту, оставляет записи за последние 7 дней (не больше `Ingest__MaxArticlesPerSource`, по умолчанию 30, самые свежие) и пропускает уже сохранённые URL.
4. Текст берётся из ленты, если там есть полный текст длиннее 400 символов (поле `full-text` или `content:encoded`). Иначе загружается страница статьи и выделяется основной текст.
5. Запись добавляется в `news_raw` со статусом `queued`, затем ставится `ParseNews`.

## Две группы источников

| Группа | Файл | Интервал | Идентификаторы |
| --- | --- | --- | --- |
| Обычные ленты | `data/sources.json` | 2 минуты (`poll_seconds=120`) | без префикса: `interfax-main`, `rbc-economy`, `kommersant-main` и т.д. |
| Специализированные (рубрики: экономика, финансы, бизнес, рынки, регулирование) | `data/sources-specialized.json` | 15 минут (`poll_seconds=900`) | с префиксом `spec-`: `spec-kommersant-finance`, `spec-vedomosti-economics`, `spec-prime-business`, `spec-banki-news` и т.д. |

Каталоги хранятся в разных файлах и загружаются в одну таблицу `source`, а интервал и префикс id различают группы. Задания собираются и ставятся отдельно для каждой группы, обработчик один. Очередь последовательная: пока идёт долгий сбор одной группы (первый заход по рубричным лентам занимает несколько минут), задание другой ждёт своей очереди. Статья, которая есть в обеих группах, сохраняется один раз (по каноническому URL) в той группе, которая собрала её раньше. Свой источник добавляется строкой в нужный файл; `poll_seconds` не меньше 60.

## Что сохраняется

- `canonical_url` без `utm_*`, `yclid`, `gclid`, `fbclid`, `_openstat` и фрагмента; значимые параметры (например `?id_4=40706` у Минфина) остаются.
- `text_sha256` считается от текста с нормализованными пробелами.
- Дата публикации: сначала из ленты, затем из страницы (`article:published_time`, `<time datetime>`, JSON-LD). Дата загрузки вместо неё не подставляется. Нет даты — статус `rejected`, причина `no_published_date`, в ленту такая запись не попадёт. Дата вне окна 7 дней — `rejected`, причина `outside_window`.
- Постоянная ошибка страницы (пустой текст, 404, неразрешённый хост) — статус `failed` и код в `last_error`. Временная (таймаут, сеть, 5xx, 429) — запись не создаётся, повтор в следующем цикле.
- В `source` обновляются `last_checked_at`, `last_success_at` и `last_error`. Сбой одного источника не останавливает остальные.

## Кодировка и обрыв ответа

Кодировка берётся из заголовка, затем из `<meta charset>`, затем проверяется UTF-8 и при ошибке используется windows-1251 (так отдаёт страницы sport-interfax.ru). Если сервер оборвал или завис на ответе, но часть данных уже получена, она возвращается как есть и из ленты читаются полные записи.

## Безопасность загрузки

Все запросы идут через `SafeFetcher`: хост адреса (и каждого редиректа) должен входить в `allowed_hosts` источника; адреса loopback, частные, link-local проверяются при подключении и отклоняются; таймаут 15 секунд, размер до 5 МиБ, не чаще одного запроса в секунду на домен. Для тестов на локальном сервере есть `Ingest__AllowPrivateAddresses=true`, в продакшене его включать нельзя.

## Особенности источников

| Источник | Особенность |
| --- | --- |
| РБК | страницы статей отдают пустой ответ за анти-бот защитой, поэтому берётся `rbc_news:full-text` из ленты `full.rss`; защиту не обходим |
| Прайм | основной текст берётся адаптером по селектору `.article__body .article__text` |
| Правительство РФ | адаптер `.reader_article_body p:not([class])`; лента приходит оборванной (заголовок объявляет больше байт, чем отдаётся), поэтому читаются полные `<item>` из полученной части |
| Минфин России | адаптер `.presscenter_one .text_wrapper p`: общий выделитель принимал за текст лицензионный футер; допускаются короткие указы (от 60 символов) |
| Русбанкрот | лента `/rss/` в windows-1251, полный текст лежит в `yandex:full-text` как дважды экранированный HTML, поэтому читатель ленты декодирует и убирает теги; страницы статей не загружаются |
| Интерфакс, Коммерсантъ | общий выделитель текста (SmartReader) без адаптера |

Для рубричных лент не подошли: РБК и Интерфакс (параметр рубрики не меняет ленту), ТАСС (разделы не фильтруются), Финам (лента не разбирается как XML). Выключены: ТАСС (общая лента), Ведомости (общая лента), ФНС (2 записи в неделю), Банк России (RSS не найден), Polpred.com (RSS нет, `robots.txt` запрещает всем краулерам раздел `/news/`, материалы платные; обход не делаем).

## Проверка

- Тесты: `dotnet test` (парсинг лент и страниц на фикстурах `backend/AlfaNews.Tests/Fixtures/ingest`, `SafeFetcher` и сбор на локальном HTTP-сервере, загрузка каталога). Фикстуры сохраняют реальную структуру страниц, а тексты статей в них заменены синтетическими.
- Живой прогон: по три статьи с каждого включённого домена, результат в комментарии к задаче.

Ограничения: сайты-источники с динамической подгрузкой текста не поддерживаются.
