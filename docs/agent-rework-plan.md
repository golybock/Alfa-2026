# План переработки агента и ленты (23.10.2026)

Рабочий документ для продолжения после сжатия контекста. Всё ниже согласовано Артёмом (он же пользователь сессии, владелец контрактов и схемы БД). Изменения не коммитятся и не пушатся. Worker без явной необходимости не запускаем: любой запуск собирает новости и пишет в базу.

## Целевой поток

1. Новость → LLM-сводка (`NewsExtraction`: заголовок, факты, теги) один раз на новость.
2. Скоринг по формуле A10 для каждой целевой компании (`Feed:CompanyIds`).
3. Порог допуска задаётся в `.env` (`Ranking__MinBase`, `Ranking__MinScore`, через Compose-переменные). Не прошла — карточки нет.
4. Прошла → сразу ставится генерация инсайта. Не по таймеру, а когда появилась новость, прошедшая скоринг и фильтры.
5. Агент получает новость, базовые данные компании и инструменты. Доказательства он берёт сам через инструменты, в том числе может найти похожие новости (`search_similar_news`) и ссылаться на несколько из них.
6. Чат по готовой карточке (A13): только контекст карточки и её доказательства плюс сообщение пользователя. Без инструментов и без новых данных; scope gate сохраняется.

Значит, постановка RefreshFeed после принятого события была верной идеей, но недоделанной. Возвращаем её только для компаний из `Feed:CompanyIds`, не для всех 10 226 профилей, с явным скорингом. Insight ставится только для событий, прошедших порог и ещё не имеющих карточки. Суточный таймер `Feed:RefreshIntervalSeconds` остаётся только для пересчёта свежести снимка, без повторной генерации существующих карточек.

## Правки (к выполнению)

1. **Без предзагрузки доказательств.** В контексте агента не должно быть реестра всех доказательств. Изначально — новость (E1) и минимальный профиль, остальное — только из результатов инструментов. Нужны новые инструменты: `search_similar_news` (FTS+e5 по `event` в недельном окне, возвращает события с фактами) и при необходимости `get_source_fragment`.
2. **Цитаты по ссылке, а не дословно.** Модель возвращает строку и диапазон символов, код сам вырезает цитату из сохранённого текста. Для новостей: в промпт подаётся текст с пронумерованными строками, `ExtractedFact` получает `line`, `start`, `end` вместо `quote` (или в дополнение к нему). Проверка чисел — по указанным строкам. Это убирает `quote_not_in_body` и смягчает `number_not_in_quote`. Затрагивает контракт (`ExtractedFact`, `EvidenceDto` при необходимости), схемы (`contracts/generate.py`), промпты `news-extract`/агента и `versions.json` с хэшами (`verify_pack.py`).
3. **Причина невалидных черновиков.** Что установлено по диагностике:
   - `claims:*:payment_overclaim` срабатывает ложно: корень «зависимост» в `InsightChecks.PaymentOverclaims` ловит фразы вроде «данных о топливной зависимости нет». Сузить список до реальных переоценок («поставщик», «покупател», «доля поставок/выручки/затрат») и применять только к утвердительным `source_fact`/`ai_inference`.
   - `claims:*:number_not_in_evidence` срабатывает на производные числа: модель пишет 82,1% как 100 − покрытие 17,9%. Решить: запретить производные числа в `source_fact` через промпт либо считать допустимыми дополнения до 100%.
   - Добавить проверку, которую пропустил и критик: «страны поставок по ФТС» — страна ФТС не доказывает поставки.
4. **Обрезать контекст.** Фрагменты PDF в контексте агента — до ~600 символов (полный текст остаётся в evidence для UI). Дубли доказательств и ограничений убрать нормализацией. Мусорные факты-цитаты вроде «— сказал Шохин журналистам» не добавлять.
5. **Критику — только доказательства, на которые ссылается черновик.**
6. **Один план и инструменты на CEO и CFO.** Убрать роль из контекста плана и из ключа операции плана/инструментов (company × event): вторая роль получит кэш шлюза бесплатно. Черновик и критик остаются по ролям.
7. **Сверка цитат новостей терпимая к кавычкам и тире**: «» " „ “ ” → ", — – ‑ → -, ё/е по ситуации. Актуально, пока не внедрён п. 2.
8. **Резерв бюджета (найдено при диагностике).** `LlmBudget.Estimate` считает токены по байтам UTF-8 (кириллица — ×2) плюс полный лимит выхода по тарифу-оценке 500 ₽/млн. Резерв черновика ~79 ₽ при факте ~2,4 ₽. Прерванный запрос (`request_started`) держит резерв до конца суток. Нужно: оценка по символам, реалистичные тарифы (наблюдаемые DeepSeek ~65 ₽/млн смешанных, GLM ~18), освобождение брошенных резервов при старте после таймаута с понятной политикой неизвестной стоимости.
9. Порог допуска (`MinBase`/`MinScore`) пробросить в `.env.example` и `compose.yaml`.

## Вторая очередь правок (23.10, вечер)

- `search_similar_news`: события, близкие к текущему по e5 (passage↔passage, порог `Embeddings:SimilarNewsMinSimilarity` = 0,84), и FTS-кандидаты только с общим тегом фактора/отрасли. В тестовой базе у несвязанных событий косинус 0,71–0,85.
- Позиция банка: `bank_view: found` только при фрагменте с датой не старше 60 дней до события и совпадением с ключевыми словами факторов события (`bank_view:not_applicable`); неподходящие фрагменты перечисляются в контексте модели, но не в карточке.
- e5 до фильтра заголовков: вектор, отсев мусора и склейка пересказа (`Embeddings:DuplicateMinSimilarity` = 0,93, только без новых чисел) в `NewsTriageService`; та же проверка в `ParseNews`. Порог 0,93 не откалиброван.
- Даты PDF в `data/bank_research/index.json`; повторный OCR с факторами (64 страницы, 17,17 ₽, 7 починок, 163 из 255 блоков с факторами); новый seed и миграция `RefreshBankResearchOcr` (проверена на копии основной базы).
- Описание `data/taxonomy.json` в `contracts/inputs.md` и `AGENTS.md`.
- Тест без рассуждений DeepSeek (тот же сценарий): извлечение новостей 3/3 без починок, 0,33–0,41 ₽ и 5–7 с вместо 0,48–1,24 ₽ и 16–24 с, качество фактов и цитат на уровне. Черновики карточек — 0 из 2: ссылки на несуществующие `E*` и числа без доказательств, починка не помогла (3,42 ₽ за прогон). Решение Артёма: рассуждения DeepSeek остаются включёнными везде (кроме фильтра заголовков, как было), флаг по задачам не вводим.

## Наблюдения по качеству карточек

- `bank_view: found` ставится на фоновых макрообзорах, хотя модель сама пишет, что это не позиция банка по событию. Нужна проверка даты и темы либо ужесточение промпта.
- Ограничения дублируются: модель перефразирует ограничения, добавленные кодом.
- Слабая релевантность: общее мнение главы РСПП встало №1 у строительной компании только через тег `government_spending` и правило «гарантия → госзаказ». Веса в `taxonomy.json` — черновик, их нужно проверить.
