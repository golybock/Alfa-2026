# A07: обработка новостей и фильтр заголовков

Реализация рассчитана на один последовательный Worker и общую PostgreSQL. Коммиты и ветки не создавались.

## Сбор и приоритеты

`CollectNewsJobHandler` вызывает существующий сборщик, затем `NewsProcessingSchedule`. При запуске Worker каталоги синхронизируются с `source`: `sources.json` — общий поток с опросом через 3600 секунд, `sources-specialized.json` — специализированный поток через 900 секунд. Планировщик проверяет сроки каждые 30 секунд, ставит отдельный CollectNews для каждого источника и исключает активные задания сбора. Фактический запрос выполняется последовательно, когда очередь доходит до задания. Ограничение в 30 статей из одной RSS снято; ограничения количества источников нет.

Миграция `20261022230230_NewsImportanceAndSourceCatalog` добавляет `source.is_specialized`, обновляет каталог из встроенного снимка 23 источников и сохраняет даты предыдущих проверок. Исторические миграции не переписываются. Текущие каталоги, контрактный seed и снимок миграции согласованы. Удаление старых новостей не включено в миграцию.

`news_raw.importance`:

| Значение | Значение для конвейера |
|---|---|
| NULL | Заголовок ещё не проверен |
| 1 | Специализированный источник или ответ yes |
| 2 | Ответ maybe, резерв очереди |
| 3 | Ответ no; rejected/headline_irrelevant, в разбор не попадает |

Общие новости проходят `TriageNewsJob`: до 50 ID и заголовков за запрос, без текстов статей. Маленький остаток обрабатывается сразу, накопления до 50 нет. Ответ `NewsTriage` проверяется схемой и кодом: все исходные ID ровно по одному, без новых ID, только yes/maybe/no. С промпта 3.0.0 (текст продакта, 24.10) фильтр строгий — «стоит ли тратить токены на полный разбор»: yes — только конкретное событие с явной экономической значимостью, maybe — узкий класс «событие и прямой канал есть, масштаба не хватает», риторика, заявления без решения и спекулятивные цепочки — no; при сомнении между maybe и no — no. Качество на разметке ALF-58 ещё не замерено. Специализированные публикации сразу получают 1.

Допуск к разбору ограничен 50 активными ParseNews: сначала 1, затем 2; внутри важности — от свежей публикации к старой (так же отбираются заголовки для классификации). После запуска лента заполняется новостями, ближайшими к текущему времени, а не произвольной частью недельного запаса источников. Задания важности 1 имеют приоритет 83, классификация — 82, сбор — 80, важность 2 — 79. Уже работающий обработчик не прерывается. Пустые места заполняются после классификации и на очередном такте расписания. При большом непрерывном потоке важных публикаций вторичные и старые могут ждать до истечения недельного окна.

При потере процесса активные задания восстанавливает существующая очередь. Планировщик подхватывает queued-строки без задания. Failed-строки автоматически не отправляются модели заново: нужен явный retry исходного задания. Успешный повтор классификации не меняет уже сохранённую оценку.

## Разбор публикации

`ParseNewsJobHandler` вызывает `NewsProcessing`: проверка включённого источника, известной даты и окна разбора (`NewsWindow`): неделя, но при первом запуске — только 3 дня до первой собранной новости, чтобы не разбирать весь недельный запас источников (окно ленты остаётся 7 дней; через 4 дня работы окно разбора снова неделя). То же окно расписание применяет до фильтра заголовков, так что старые публикации не тратят и классификацию; сохранён допуск сборщика для часов источника до суток в будущее. Отсутствие даты, старый текст, пустое тело и обнаруженный футер сохраняются с причиной отказа до LLM. Сборщик также отклоняет известный вариант футера Copyright/«Все права защищены» вместо статьи; это узкая защита, а не универсальная оценка качества парсинга.

Совпадение нормализованного SHA-256 с готовым событием создаёт `event_source`, помечает новость duplicate и не вызывает LLM. Canonical URL уже защищён уникальностью при сборе.

e5 считается до фильтра заголовков: `NewsTriageService` для каждой новости пачки сначала строит вектор (он сохраняется в `news_raw.embedding`), отклоняет явный мусор и может искать пересказ — событие за два дня до и день после публикации с косинусом не ниже `Embeddings:DuplicateMinSimilarity`. По умолчанию порог 1, то есть склейка по e5 выключена: калибровка на ~500 реальных новостях показала, что косинус не отличает пересказ от обновления сюжета ([отчёт](calibration-thresholds.md)); остаются точные дубли по SHA-256 и URL. Пересказ склеивается, только если в тексте новости нет чисел, которых нет в событии: публикация с новыми числами проходит извлечение отдельно. Склеенная новость получает `event_source`, статус `duplicate` и причину `semantic_duplicate` без вызова LLM. В фильтр заголовков уходят только оставшиеся. `ParseNews` использует сохранённый вектор и повторяет проверку пересказа перед извлечением: так ловятся две перепечатки из одной пачки. Если включить склейку, рекомендуемый минимум — 0,97 с ручной проверкой.

Локальный `NewsEmbeddings` обращается к существующему TEI `/embed`, проверяет 768 конечных ненулевых значений. Генеративных моделей вне LlmGateway нет. Для статьи используется `passage:`, для экономических и посторонних контрольных тем — `query:`. Явно посторонняя тема отклоняется только при cosine не ниже 0,79 и превосходстве над экономическими темами не меньше 0,04; сомнительные проходят. Порог проверен на небольшой контрольной выборке, большой размеченной оценки ещё нет. Если TEI недоступен или ответил ошибкой, e5-фильтр пропускается: в `filter_json` пишется `decision=e5_unavailable`, событие сохраняется без вектора, извлечение DeepSeek и точный дедуп по URL/хэшу продолжают работать.

Извлечение вызывается через LlmGateway. Тело статьи передаётся пронумерованными строками (`NewsLines`: абзацы, разбитые на предложения). Модель возвращает `NewsExtractionDraft`: у каждого факта есть текст, номер строки и необязательный диапазон символов `start`/`end` внутри строки. Сама модель цитату не пишет — код вырезает её из указанной строки и сохраняет в `ExtractedFact.quote` вместе со ссылкой. Проверки: строка существует, диапазон корректен, все числа текста факта есть в цитате (если их нет в диапазоне, но они есть в строке, берётся вся строка), теги разрешены. Максимум одна починка. Факторы берутся из `factor`, отрасли — из `sector_sensitivity`, страны — из общего русского `CountryNames`, как в профилях компаний. Пока согласованные словари регионов и commodities не подключены, эти массивы пустые; отсутствующие факторные/отраслевые справочники также не выдумываются.

В одной транзакции сохраняются `event`, `event_source`, `event_tag`, русский FTS и e5-вектор. Повтор готового события не оплачивает извлечение. Диагностика отказа хранится в `filter_json`, код ошибки — в `last_error`. Неснятый после починки дефект оставляет failed и не создаёт событие. После сохранения событие сразу проходит скоринг по формуле для компаний из `Feed:CompanyIds`. Если оно проходит порог хотя бы для одной из них, ставится RefreshFeed этой компании (если такой ещё нет в очереди), и уже он ставит генерацию карточек ([A10](a10-ranking.md)).

Словарь `TAXONOMY_JSON` для извлечения: факторы из таблицы `factor` (синхронизируется из `data/taxonomy.json` при старте Worker), полный справочник классов ОКВЭД2 (`Okved2Names`) и страны `CountryNames`. Регионы и сырьё пока пустые.

## LLM и запуск

Для NewsTriage и его Repair используется DeepSeek-V4.1-Flash с `thinking=disabled`, предел ответа 6000 токенов. Остальные задачи DeepSeek сохраняют прежние настройки. GLM остаётся low; `Llm:TriageUseGlm` предназначен для сравнения маршрутов, по умолчанию false. Mock возвращает maybe для каждого переданного ID; это не оценка качества живой модели.

TEI доступен локально только на `127.0.0.1:18081`; в Docker Worker использует `http://tei:80`. После `docker compose up -d tei postgres` можно запускать Worker через `dotnet run --project backend/AlfaNews.Worker -- run-worker`. Live-режим и ключ задаются только окружением; штатный режим — mock. Основной Worker после проверки оставлен остановленным.

Для воспроизводимой ограниченной проверки добавлена команда:

```text
dotnet run --project backend/AlfaNews.Worker -- news-validate data/cache/a07-report.json interfax-main 4
```

Требуется отдельно созданная пустая БД с именем `alfanews_a07_*`, настроенная через `ConnectionStrings__DefaultConnection`, и доступный локальный TEI. Команда применяет миграции, собирает выбранный общий источник, исполняет реальные задания сбора/классификации, сравнивает GLM на том же списке заголовков, обрабатывает 1–10 публикаций и проверяет отсутствие нового HTTP-вызова при повторе принятой. Планировщики и основной Worker при этой команде не запускаются. Бюджет дополнительно ограничен 150 ₽ или меньшим настроенным суточным лимитом этой тестовой БД. Общий лимит команды организаторов не изолируется PostgreSQL разных стендов.

## Проверка 23.10.2026

Основная БД уже не содержала news_raw/event. По разрешению пользователя удалены 152 оставшихся ParseNews и 3 CollectNews; PDF, компании, профили и журнал расходов сохранены. Для живой проверки использованы отдельные `alfanews_a07_validation` и `alfanews_a07_final`; основной Worker не включался.

| Прогон | Заголовки | DeepSeek без thinking | GLM low |
|---|---:|---|---|
| Первый | 25 | 5,405 с; 0,16727985 ₽ | 7,791 с; 0,19210587 ₽ |
| После защиты от футера | 22 | 4,866 с; 0,15097472 ₽ | 9,667 с; 0,18107917 ₽ |

Обе модели вернули схему и все ID без починки. В первом прогоне совпали 20/25 оценок, во втором — 11/22. Во втором DeepSeek дал 7 yes / 14 maybe / 1 no, GLM — 14 yes / 6 maybe / 2 no. При ручном просмотре GLM чаще повышал общеполитические заявления до yes, но конкретный оборонный производственный контракт оценил maybe. DeepSeek оставлен основным: на этих двух запросах он быстрее и дешевле; это небольшая выборка без утверждённой gold-разметки, не доказательство общей точности.

В окончательном прогоне сборщик получил 25 записей: 22 готовы к фильтру, 3 остановлены до LLM как неподходящий текст. Из четырёх попыток извлечения созданы три события; четвёртая осталась failed/news:quote_not_in_body после одной починки. Повтор принятого события не увеличил количество HTTP-попыток. Расход окончательного прогона — 1,94530889 ₽, первого — 2,20879052 ₽, суммарно **4,15409941 ₽**, неизвестных расходов нет. Политика проверки цитат не ослаблялась ради успешного результата.

Контроль локального e5: спортивный результат и личная жизнь отклонены; ключевая ставка, нефтяные санкции и финансирование стадиона допущены. Интеграционные тесты проверяют exact-дубль без нового LLM, похожий текст с новым числом, FTS/вектор/теги/RefreshFeed, недельное окно, футер, три оценки, пакетный допуск, приоритет важных, сбор 40 статей и интервалы 15/60 минут. Логи и сырые результаты находятся в игнорируемом `data/cache`, в Git не добавляются.

## Файлы и зависимости

Worker разделён на `News`, `Documents`, `Importing`, `Profiles`, `Queue`, `Evaluation`, пространства имён сохранены. Новых NuGet/npm-пакетов нет. Существующие TEI и multilingual-e5-base добавлены в THIRD_PARTY_NOTICES с лицензиями. Устранена дублирующая регистрация GET /api/jobs/{id}, найденная при интеграционном тесте PDF после объединения изменений.

Документация компонентов: [TEI API](https://huggingface.github.io/text-embeddings-inference/), [e5 model card](https://huggingface.co/intfloat/multilingual-e5-base).
