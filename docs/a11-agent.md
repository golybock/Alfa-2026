# A09, A11, A12: поиск аналитики банка и агент карточки

## A09: индекс и поиск

`EmbedContentJob` (полоса documents) считает e5-вектор фрагмента `research_chunk`: название документа, текст, заголовки таблиц и описания графиков с префиксом `passage:`. Устаревшая версия фрагмента пропускается (`stage=stale`). Планировщик сам ставит индексацию фрагментов без вектора, в том числе для девяти PDF из seed.

`ResearchSearch.SearchAsync` объединяет русский FTS (`websearch_to_tsquery` по словам запроса и ключевым словам факторов через OR) и cosine-поиск pgvector через RRF (k=60) и возвращает до шести фрагментов с названием, датой, страницей, видом блока и статусом сверки. Числа графиков отдаются только для графиков со статусом `reviewed`. Если TEI недоступен, остаётся FTS.

Не реализовано: ручная сверка `ApplyReview` (A09.4–A09.5) и её endpoint D10.

## A11: план, инструменты, черновик

`InsightAgent` обрабатывает `GenerateInsightJob` (полоса insights):

1. Создаёт или берёт `insight` нужной версии (`processing`) и общий `agent_run`.
2. Пересчитывает ranking события, берёт relevance и доказательства причин из снимка ленты. Остальные доказательства заранее не загружаются: факты новости в контексте пустые, модель получает их через `get_event`.
3. До двух планов DeepSeek (`AgentPlan`), всего до пяти вызовов инструментов, поиск аналитики — не больше двух раз. План общий для CEO и CFO: роли в его контексте нет, поэтому вторая роль получает план из кэша шлюза бесплатно (аргументы инструментов приводятся к каноническому порядку ключей, иначе jsonb кэша ломал совпадение второго раунда). Инструменты только читают данные: `get_company_profile`, `get_event` (факты новости с цитатами; служебные фразы вроде «— сказал он журналистам» отбрасываются), `get_group_summary`, `get_payment_exposure`, `search_bank_research`, `search_similar_news` (FTS + e5 через RRF по событиям недельного окна, до пяти, без текущего). Компания и событие берутся из задания, аргументы проверяются JSON Schema. Если модель не вызвала `get_event` или поиск аналитики, код выполняет их сам (`default_event`, `default_search`).
4. Перед черновиком код проверяет, какие фрагменты аналитики банка годятся как позиция банка по событию: есть дата документа, она не раньше чем за 60 дней до события и не позже даты расчёта, и текст фрагмента совпадает по полнотекстовому поиску с ключевыми словами факторов события. Неподходящие перечисляются в контексте черновика и критика (в карточку эта пометка не попадает), а `bank_view: found` с опорой только на них отклоняется проверкой `bank_view:not_applicable`. `search_similar_news` берёт события недельного окна, близкие к текущему событию по e5 (косинус passage↔passage не ниже `Embeddings:SimilarNewsMinSimilarity`, по умолчанию 0,84), и FTS-кандидатов только с общим тегом фактора или отрасли; пустой результат допустим.
5. Черновик `InsightDraft` получает `AgentContext`: роль, компанию, контур новости, ranking, реестр доказательств и ограничения. Цитаты длиннее 600 символов в контексте обрезаются; в карточке остаётся полный текст. Ограничения кода модель не повторяет: они добавляются в карточку кодом, дубли убираются нормализацией текста. Критик получает только доказательства, на которые ссылается черновик.

Каждый шаг пишется в `agent_step` с аргументами и результатом инструмента.

## A12: проверки, критик, починка

Кроме проверок шлюза (схема, существующие `C*`/`E*`, числа графиков без сверки), `InsightChecks` требует:

- `bank_analytics` — только со ссылкой на материал банка;
- гипотеза — с `confidence`;
- числа в `source_fact`/`bank_analytics` — из процитированных доказательств; дополнение доли или покрытия до 100% допустимо;
- никаких «поставщиков», «доли выручки/затрат/поставок/закупок» на основании платёжных агрегатов (только утвердительные `source_fact`/`ai_inference`, фразы с отрицанием не ловятся);
- страны ФТС не выдаются за страны поставок (`fts_overclaim`);
- `bank_view=found` — только с утверждениями банка и хотя бы одним применимым фрагментом (`bank_view:not_applicable`);
- непустые заголовок и «что произошло».

Ошибка кода тратит единственную починку шлюза. Если и она не прошла, карточка `failed`, критик не вызывается.

Критик GLM вызывается один раз. Отключён → `skipped_disabled`, нет бюджета → `skipped_budget`, ошибка или timeout → `skipped_error` без повтора. При замечаниях, если починка ещё не использована, выполняется одна починка с диагностикой критика; второго критика нет. Утверждение из замечаний, которое не изменилось или для которого починка не прошла, получает `not_confirmed`, исчезает из действий и отражается в ограничениях. Утверждения без замечаний — `critic_passed`, изменённые починкой — `code_passed`.

Готовая карточка сохраняется в `insight.body_json` как `InsightDto`; `trace_id` — ID `agent_run`. В mock-режиме фикстура черновика пустая и не проходит проверку «что произошло», поэтому карточка честно получает `failed`; успех не имитируется.

Тесты: `InsightAgentDatabaseTests` (полный цикл со скриптованной моделью, починка по замечаниям, неснятое замечание, timeout критика, невалидный черновик) и `ResearchSearchDatabaseTests`.
